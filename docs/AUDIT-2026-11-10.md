核心学习闭环（取词 → 出题 → 判分 → SM-2 → 统计 → 锁屏）能跑，日语配置最完整。但代码里“有实现”和“实际生效”差距很大：朗读题、错因诊断、作业提交、被动答题、浅色主题、多语言统计这六块存在实质性断链。

在加本地 ASR 之前，必须先修数据正确性；否则新题型会建在已被污染的 SM-2 数据上。

## 2. 半成品 / 断链（按功能）

### 2.1 朗读题 read_sentence：四重损坏

1. **目标文本错误**
   backend/internal/api/handlers_quiz.go:934-949：
   - 只要 stype == “word”，就取 word.Reading 当目标文本；
   - read_sentence 的 SubjectType 也是 “word”，所以永远拿单词读音去评用户读的句子；
   - 缓存里的句子答案永不消费。

2. **生成指引缺失**
   backend/internal/ai/prompts/generate.yaml 只有 choice/fill/reading/listening/reading_comp/grammar，没有 read_sentence；
   同文件 :7 要求所有文本用 ExplanationLang，和目标语言句子冲突。

3. **AI 题 ID 碰撞**
   backend/internal/api/question_gen.go:144-152 的 ID 是 ai-%c-%d，read_sentence 与 reading_comp 首字母都是 r，同一个 word 生成两类题时 ID 都是 ai-r-<id>，questionCache 互相覆盖。

4. **平台覆盖不足**
   read_sentence 仅 tier3；en/zh/ko 的 pronounce.provider 为空；即使 ja 有 provider，上面三条也会让它不可用。

### 2.2 学习卡跟读偷偷算进 SM-2

- backend/frontend/lib/screens/quiz_session_page.dart:243-256 硬编码 questionType: ‘read_word’、questionId: ‘study_<id>’ 提交到 /quiz/submit。
- 后端没有这个缓存题，走 handleReadAloudSubmit → writeReadAloudResult，照样推进 SM-2、写 review_log、写 daily_stats。
- VISION 说“跟读不算 SM-2”，实际会计入复习与每日目标。
- 录音失败/无 provider 时 recordReadAloudFallback（handlers_quiz.go:899-919）按 quality 2 记失败，还会污染 EF。

### 2.3 错因诊断：后端通，前端 0 接入

- error_category、/stats/diagnostics、/quiz/dispute 后端都已实现。
- 前端 quiz_api.dart 有 dispute，quiz_session_page.dart:1377 也确实显示了“我觉得判错了”。
- 但 StatsApi 没有 diagnostics 方法，统计页只有 streak + heatmap；“错因标签/纠正建议/诊断展示”没有任何 UI。

**更正**：此前“P1 前端 0 接入”的说法不准确；dispute 已接，只有 diagnostics 面板没接。

### 2.4 作业提交：ID 类型不一致

- 生成时返回 genAssignmentID() 字符串（如 a-s-150405），InsertAssignment 写的是自增整数，且错误被忽略。
- 前端回传字符串 ID，CompleteAssignment(id string) 用 WHERE id=? 永远匹配不到 → 刚生成的作业永远无法标记完成。
- handleAssignmentSubmit 的 topic 固定取 pending[0].Prompt，多个 pending 时会批改错题。

### 2.5 被动学习：只有提醒，没有题

- provider_windows.go:796-886 只建 320x200 窗口画“复习提醒”，没有题目/作答/提交。
- 前端 getPassiveQ/passiveSubmit 无任何调用点；l10n 自己写着“Coming Soon”。
- main.go:184-192 只用 PassiveMinInterval，PassiveMaxInterval 从未使用。
- 配置面板三项 passive 控件后端没有写入路径，是死控件。

### 2.6 配置类断链

- handleConfigPassword 直接 501（handlers_config.go:292-298）；Onboarding 的“设置密码”只写 debug 日志，用户以为设置成功。
- DailyTimeTarget 注释仍说“按时间解锁”，实际 DailyTargetMet 只看计数+准确率；设置无效。
- 浅色主题不持久：app_state.dart:396 只处理 vs-dark，浅色配置重启后仍是深色；app.dart 传给 MaterialApp 的 theme/darkTheme 还是同一份 AppTheme.themeData。

### 2.7 统计口径错误

- daily_stats 初始表 date TEXT PRIMARY KEY，Phase 8 才加 language 和 UNIQUE(date,language)；同一天写第二种语言直接报 UNIQUE constraint failed: daily_stats.date（已用临时测试复现）。
- DailyTargetMet（server.go:155-190）分子/分母用唯一题数，accuracy 分子却用总尝试正确数；同一词答对两次 accuracy=2.00，会错误放行目标。

### 2.8 其他半成品

- meaning 未在任何语言启用；BuiltinLanguage(“en”) 只有 5 种题型，模板有 9 种，英语会少 listening/grammar/reading_comp/read_word/read_sentence。
- AI 出题直接 json.Unmarshal，代码围栏就解析失败并回退 choice；题型还信任 AI 返回的 type，不强制请求的 qType。
- GenerateReadSentence 定义在 engine/question.go:204-216，全库无调用。
- unlockNextSense 想插同拼写新义项，但 words 有 UNIQUE(word,language) 且 InsertWord 用 INSERT OR IGNORE，永远插不进去，是无效功能。
- 词库扩词 dict 命中会无条件覆盖用户已填的 reading/meaning/POS；批量 accept 可把 rejected/active 重新激活。
- /quiz/submit 缓存 miss 时按 quality 0 推进 SM-2 再返回“Question expired”（handlers_quiz.go:537-619），服务重启/缓存淘汰会冤枉用户。

## 4. 风险（按严重度）

### P0 — 数据正确性

1. 朗读链路污染 SM-2：系统错误、跳过、学习卡跟读都推进复习计划；无 provider 也按 quality 2 记失败。
2. read_sentence 用单词评分，且缓存句子永不消费，缓存留 15 天或被随机挤掉。
3. daily_stats 多语言写入失败 + accuracy 可 >1，每日目标门可能误放行。
4. 作业 ID 字符串/整数不匹配，作业永远完不成。
5. 缓存 miss 当答错，重启会改变用户复习数据。
6. AI 题 ID 碰撞，同类题互相覆盖。

### P0 — 数据丢失 / 安全

7. Git：4 个多月未提交、master ahead 3、backend/.git 无 remote 且还残留 convo 删除记录，根仓库又跟踪 backend 文件；一旦误操作/看错仓库，改动可能全丢。
8. Token 泄漏：main.go:218 明文打印 token，且通过 --auth-token 命令行传给 Flutter，进程列表可见；middleware 全路径接受 ?token=。
9. AI Key 落盘：SaveAppConfig 直接 marshal AI.APIKey，handleConfigUpdate 每次保存 app.yaml；用环境变量藏 key 的部署会被写回磁盘。
10. 无请求体限制：readJSON 无 MaxBytesReader；导入、AI chat history/message、TTS 文本都无长度/条数上限，可放大内存与 API 费用。
11. Windows 锁屏只是视觉遮罩：WM_NCHITTEST 返回 HTTRANSPARENT，无键盘钩子/BlockInput，Alt+Tab、Win+D、任务管理器均可绕过（代码审查判断，未实机验证绕过）；ExitLockMode 在 HTTP goroutine 里 PostQuitMessage，线程不对，可能解锁不生效/窗口残留。
12. 消息泵无线程锁定：lockMessageLoop/trayMessageLoop/triggerPassivePopup 都没 runtime.LockOSThread，Win32 消息队列可能偶发不响应。

### P1 — 稳定性

13. 配置 map 并发读写无锁；重启 srv.Config=cfg2 无 configMu、不重新 WireAI。
14. questionCache 2000 上限随机淘汰，AI 题答案丢失；read_sentence 缓存不消费。
15. 错误大面积被吞：InsertReviewLog、UpsertDailyStats、SaveAppConfig、InsertAssignment、CompleteAssignment、SetAutoStart 等只 log 或忽略。
16. SQLite 未开 foreign_keys，migrations 无事务；grammar 日志 word_id=0 的潜在外键问题。
17. TTS/Dict provider 无内置超时；pronounce 不校验/夹取 score；TTS 缓存 Put 忽略 copy 错误。
18. 前端 _submit/_submitRecording 无 try/catch，异常后 _submitting 永远 true；config 每次刷新新建 TabController 不 dispose；多处 use_build_context_synchronously。
19. 浅色主题、深色下硬编码 Colors.red.shade50 / Colors.white / GitHub 绿阶，实际观感与已确认设计稿不是一套。

### P2 — 质量

20. 测试薄：Flutter 仅 3 个文件 11 个测试，无真实 API/录音/锁屏/主题测试；Go 无端到端启动测试。
21. CI 只有 Go；未提交的 diff 新增 frontend job，但 flutter analyze 当前退出 1，会红。
22. 文档漂移：README 说 MIT、实际 PolyForm Shield；README 10 种 / SUMMARY 9 种；tier 表与实际 question_select.go 不一致；VISION 说 P4 未实现但代码已有。
23. l10n 缺口：语法详情页硬编码中文、heatmap 图例中文、作业 diary 无映射、Onboarding 只解析中文时长。

## 6. 结论与执行顺序

一句话：核心学习闭环能跑；但朗读、诊断、作业、被动、浅色主题、多语言统计这六块是“有代码、没闭环”。在加上本地 ASR 之前，必须先修数据正确性。

建议顺序：

1. 先 commit + push 现有 81+79 个文件，清理 backend/.git 假仓库，避免 4 个月工作丢失。
2. 修 P0 数据 bug：朗读目标文本/学习卡语义、daily_stats 复合主键、accuracy 分母、作业 ID、缓存 miss、AI 题 ID。
3. 修安全：token 不打印、不落 app.yaml、请求体上限、锁屏补键盘钩子/线程锁定。
4. 再开 feat/local-asr：新增 internal/asr provider（本地 whisper.cpp / faster-whisper 外部二进制，16k mono WAV 直接复用现有录音），两个“对答式造句”题型共用 ASR 输出，手敲版走文本判分、朗读版走 ASR + AI 语义批改。
5. 最后补前端诊断/作业/被动三块 UI。
